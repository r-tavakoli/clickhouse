MINMAX

Suppose a granule contains:

order_date:

2026-01-01
2026-01-02
...
2026-01-31

The minmax index stores approximately:

min = 2026-01-01
max = 2026-01-31

Now:

WHERE order_date = '2026-03-15'

ClickHouse can immediately determine:

2026-03-15 > 2026-01-31

→ impossible
→ skip granule

✅ Excellent use case.

Bad minmax example

Imagine a granule contains:

1
999999
50
700000
12
...

So:

min = 1
max = 999999

Now query:

WHERE value = 500000

The minmax index says:

500000 is between 1 and 999999

Therefore: "Maybe this value exists."

It can't skip the granule.

If this happens across almost every granule, the index isn't very useful.

❌ Not useful.

⭐ The important concept

Good skipping index

Granule 1: 1     → 100
Granule 2: 101   → 200
Granule 3: 201   → 300
Granule 4: 301   → 400

Query:

WHERE value = 250

Only Granule 3 needs to be read.

Bad skipping index

Granule 1: 1 → 1,000,000
Granule 2: 2 → 999,999
Granule 3: 5 → 999,995
...

Almost every granule overlaps.

Little can be skipped.

⚡ ClickHouse Mindset — Index to skip, not to find.
