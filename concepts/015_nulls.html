❓ Nullable Columns in ClickHouse

In ClickHouse, allowing a column to contain NULL has storage and query-processing implications. The goal is to use it when the data genuinely requires it, rather than making every column nullable by default.

1. The Problem — Missing Data

Imagine your orders table has these records:

order_id country payment_method
101IranCard
102SpainCash
103LebanonNULL
104NULLCard

What does NULL mean here?

  • Order 103: the payment method is unknown or wasn't recorded.
  • Order 104: the country is unknown or missing.

⚠️ NULL is not the same as an empty string (''), zero (0), or the text 'NULL'.

For example:

NULL       -- missing/unknown value
''         -- an empty string
'NULL'     -- the literal text NULL
0          -- numeric zero

These values can have different meanings in your business logic, so don't treat them as interchangeable.

2. How Do You Define a Nullable Column?

In ClickHouse, columns are non-nullable by default unless you explicitly define otherwise.

For example:

CREATE TABLE test_db.customer_feedback
(
    customer_id UInt32,
    rating Nullable(UInt8),
    comment Nullable(String)
)
ENGINE = MergeTree()
ORDER BY customer_id;

Here:

  • customer_id must contain a numeric value.
  • rating can contain a rating or NULL.
  • comment can contain text or NULL.

Insert some sample data:

INSERT INTO test_db.customer_feedback
VALUES
    (1, 5, 'Excellent'),
    (2, 4, 'Good'),
    (3, NULL, 'No rating provided'),
    (4, 0, NULL);

💡 Notice that customer 4 has a rating of 0, which is different from customer 3's missing rating.

If zero is not a valid business rating, you may choose a different data model. The important thing is to preserve the meaning of the data.

3. How Do You Query NULL Values?

This is an important difference from ordinary comparisons.

Find missing ratings

SELECT *
FROM test_db.customer_feedback
WHERE isNull(rating);

Find ratings that are present

SELECT *
FROM test_db.customer_feedback
WHERE isNotNull(rating);

Replace NULL with a default value in query results

You can use ifNull():

SELECT
    customer_id,
    ifNull(rating, 0) AS rating
FROM test_db.customer_feedback;

This returns 0 for customers without a rating, but does not modify the stored data.

You can also use coalesce() when you have multiple fallback values:

SELECT
    customer_id,
    coalesce(comment, 'No comment') AS comment
FROM test_db.customer_feedback;

A common mistake

❌ Don't write:

WHERE rating = NULL

✅ Use:

WHERE isNull(rating)

A missing value isn't an ordinary value that you compare with =.

4. How NULL Affects Aggregations

Suppose you run:

SELECT
    count() AS total_rows,
    count(rating) AS rated_rows,
    avg(rating) AS average_rating
FROM test_db.customer_feedback;

The results are conceptually:

Metric Result
total_rows4
rated_rows3
average_rating3

Why?

  • count() counts all rows.
  • count(rating) counts non-NULL ratings.
  • avg(rating) ignores NULL values when calculating the average.

The average is:

(5 + 4 + 0) / 3 = 3

⚠️ This matters in business analytics. If you replace missing ratings with zero before calculating the average, you change the business meaning of the metric.

Rule: Missing values should only be converted to zero when zero is genuinely the correct business interpretation.

5. Why Can Nullable Affect Performance?

ClickHouse stores the actual column values alongside information indicating which rows are NULL. This null mask introduces additional storage and processing overhead.

For example:

rating UInt8

is a simpler representation than:

rating Nullable(UInt8)

💡 But this does not mean you should remove every nullable column.

Consider these cases:

Column Recommended Approach Reason
quantity Usually non-nullable Missing quantity should typically be rejected or handled during ingestion
discount_amount Depends on business meaning NULL may mean unknown, while zero means no discount
customer_comment Nullable if absent comments mean missing data An empty string may have a different meaning
delivery_date Nullable if orders may not yet be delivered A placeholder date could be misleading

A practical schema-design rule:

Avoid Nullable when missing data has no meaningful distinction from the type's default value. Use it when that distinction matters.

🚨 Don't silently convert missing values into defaults just to save storage.

Summary

Concept Description
Nullable(T) Allows a column to store NULL in addition to type T values
NULL semantics Missing/unknown — not the same as '', 0, or 'NULL'
Querying Use isNull() / isNotNull(), not = NULL
Aggregations count(col) and avg(col) skip NULL values
Performance Nullable adds a null mask, increasing storage and processing overhead
Best practice Use Nullable only when missing data is meaningfully different from a default

💡 Key Takeaway: Nullable is about semantics, not convenience. Use it deliberately to preserve the meaning of missing data.
